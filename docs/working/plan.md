## 2. Архитектура

### Текущая реализация

Серверная часть находится в `main.py`. Подключение к PostgreSQL выполняется
через Psycopg. API и БД запускаются через Docker Compose на стенде `kanban-test`.
API доступен на порту 8002 виртуальной машины; внутри контейнера Uvicorn
слушает порт 8000. Данные PostgreSQL сохраняются в томе `postgres_data`.
Параметры подключения задаются через `.env` и переменные окружения.
Файл `.env` исключён из Git.

### Планируемая архитектура

Клиент-сервер (ТСФ-002). React, JWT, каталог `src/kanban_board`, SQLAlchemy
и Alembic пока не реализованы.

```text
Браузер (React + TypeScript)
        │ HTTP(S), REST API, JWT
        ▼
FastAPI (src/kanban_board)
  ├── api/      — маршруты
  ├── services/ — бизнес-логика: WIP-лимиты, перемещения, права
  └── db/       — модели SQLAlchemy
        │
        ▼
PostgreSQL (схема версионируется через Alembic)
```

Перемещение карточки планируется выполнять в одной транзакции (ТН-001):
изменять колонку и позицию карточки, сдвигать позиции соседних карточек
и добавлять запись в историю.

## 3. Черновая схема БД

В текущем прототипе существует только таблица `cards` с полями `id` и `title`.
Она создаётся приложением при обращении к маршрутам карточек.
Приведённая ниже схема является планом дальнейшей разработки.

| Таблица | Основные поля |
| --- | --- |
| `users` | id, email, password_hash, name, created_at |
| `refresh_tokens` | id, user_id, token_hash, expires_at |
| `boards` | id, title, owner_id, created_at |
| `board_members` | board_id, user_id, role (owner / member) |
| `columns` | id, board_id, title, position, wip_limit (nullable) |
| `cards` | id, board_id, column_id, title, description, priority, due_date, position, assignee_id, created_by, archived_at |
| `labels` | id, board_id, name, color |
| `card_labels` | card_id, label_id |
| `comments` | id, card_id, author_id, text, created_at |
| `card_moves` | id, card_id, from_column_id, to_column_id, moved_by, moved_at |
| `audit_log` | id, board_id, user_id, action, entity, entity_id, created_at |

Таблицу `card_moves` планируется только дополнять (ФХД-002).
История перемещений будет использоваться для расчёта lead time и cycle time
(ФХД-003); правила расчёта метрик предстоит уточнить.
